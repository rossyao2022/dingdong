## 版本库里有什么、没有什么

推送/克隆之前先认清边界（规则落在根目录 `.gitignore`）：

- **不进库**：`材料/`（对方提供的对接文档、网页归档与原始数据，第三方材料）、`参考代码/dingdong/`（外部参考仓库快照）、`dist/`（发布包）、`.workbuddy/`（协作工具的项目数据）、`node_modules/`、`.venv/`、`frontend/docs/`（前端验收截图与本机记录，约 15MB，只在本机留存；正式证据见 `deploy/evidence/**`，那部分进库）。
- **凭据与环境变量值一律不进库**：`.env` / `.env.*`（`.env.example` 例外）、`*.pem` / `*.key` / `*.p12`、`**/*creds*.env`、`**/credentials*.json`、SSH 私钥。验收凭据只经环境变量传递（见 `frontend/deployment-tests/`），**不写进仓库**。
- **我方文档与证据进库**：`deploy/**`（交付文档与 `evidence/**` 证据）、`文档/`、`设计/`、`需求/`、`backend/`、`frontend/`。
- **文档与证据里的路径一律写成仓库相对路径**，不写 `/Users/<本机账号>/...` 绝对路径——Markdown 链接写成相对所在目录的形式（如 `../设计/x.md`），日志与堆栈写成从仓库根起的路径（如 `backend/tests/x.py:6`）。这样换机器、换目录仍可点开。2026-09-17 已把历史文档与证据里的绝对路径统一改写（26 个文件）。

## 后续如何保持一致

在项目根目录执行：

```sh
uv run --directory backend python ../scripts/audit_documents.py --generate
```

该命令根据本地 OpenAPI 和 Django 模型更新字段文档，然后检查文档文件链接、归档哈希/ZIP、提取文字/CSV及契约引用，输出本轮校验 JSON；不改原材料、不读写家庭业务数据、不触发外部服务。单独运行 `python3 scripts/audit_documents.py` 只做校验。它不是完整 OpenAPI 标准验证器，也不代替运行时 API 和浏览器测试。
