# 界面文字与重点审查

日期：2026-10-02。对象：本地 v0.3.27，Git 起点 `c691ec1`。本轮是审查，以下改法尚未实施，未推送或部署。

## 结论

确实存在文字遮住重点的问题，集中在三种写法：一个意思介绍多次、主动作前放太多铺垫、没有数据也铺完整页面。首页已经有按实际进度变化的主动作，这是现有优点；问题是后面的介绍和入口继续争夺注意力。无需削掉功能或把所有说明一律折叠，应按当前状态决定先显示什么。

## 核查范围与证据边界

- 本次用真实 Chrome 打开当前本地登录页，在 390×844 视口检查首屏，并读取实际 DOM 的位置和文字。没有登录、发送短信、创建家庭或调用供应商。
- 登录后页面依据 v0.3.27 已留存的合成数据浏览器截图，逐项与当前渲染代码核对。没有把这些截图说成本次重新完成的登录后验收。
- 指纹、首页模块介绍与运营工作首页的补充截图来自 v0.3.25；`git diff b935c30 HEAD` 确认 `frontend/fingerprint.js`、`frontend/playworld.js` 和运营 `dashboard.html` 未变。首页兴趣岛介绍另核对当前 `island-explorer.js`。
- 本机 8017 后端在监听；经本轮启动的 4173 前端读取 `/api/v1/runtime` 返回 development、fixed_code、database_fixture、exhibition_enabled=false。截图中的展会入口来自先前启用展会的验收环境，不能据此断言本机当前也启用。
- 未运行业务回归测试，因为本轮未改功能。审查不是用户可用性实验，下列优先级属于基于页面和代码的判断。

## 建议实施顺序与验收

第一批处理首页、无记录报告页和运营首页：删重复介绍、按数据状态调整主动作、折叠统计口径。第二批处理报告明细、指纹首屏、引导偏好和公共外壳。所有入口、历史记录、绑定权限、测评保存和现有业务链路保留。

验收时用 390×844 和 320px 宽视口检查首次、进行中、已完成、未绑定、已绑定、失败状态：当前任务有一个明显主动作；操作说明只在需要的位置出现；没有数据时能直接开始；图表边界与照片处理说明清楚可见；键盘也能查阅收起的详情。关键交互仍须使用真实浏览器验证，不能只统计字数或检查水平溢出。

现有[文案规范](../.trellis/spec/frontend/ui-conventions.md)已经要求“只放当前能做的事、操作后果和必须告知的限制”。本轮问题主要是页面累加内容时未持续执行这一原则；无需另造一套术语。该规范另含部分早期状态描述，本轮不据此改变用户后来确认的业务边界。
