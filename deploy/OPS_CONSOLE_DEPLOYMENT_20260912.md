## 2. 从 v0.3.0 到 v0.3.2：验收发现的三件事

v0.3.0 的代码和文档是完整的，但**只有真正部署到公网、用真实浏览器点一遍**，
才暴露出下面三个问题。它们都不是"少写了一个页面"，而是"写了但用不了"。

### 2.1 v0.3.1 —— 运营后台在 Docker 部署下根本打不开

`deploy/nginx.conf.template` 的代理白名单只有 `api/|admin/|static/`，漏了 v0.3.0
新增的 `ops/`。Django 容器里 `/ops/` 与 `/static/ops/*` 都正常，但请求在容器
nginx 层就被 `try_files` 当成静态文件、返回 nginx 404。

为什么之前的验收没发现：本地跑的是源码 `runserver`，绕过了容器 nginx；本地
Docker 演示环境虽然是容器，但当时没有针对 `/ops/` 做断言。

修复：白名单补 `ops/`，并新增 `deploy/tests/test_nginx_routes.py`——从
`backend/config/urls.py` 解析所有顶层前缀，断言 nginx 逐条转发。以后新增 Django
顶层前缀而忘记改 nginx，测试会直接红。

### 2.2 v0.3.2 —— 管理员的按钮点了没用

运营后台把 `account_admin` 定义为"全部权限"（`ops/permissions.py`），页面因此
对管理员显示"发布""重试该任务"；但这些动作复用的是 `/api/v1/staff/*`，那里按
具体角色放行（发布要 `content`、重试要 `technical`）。结果：管理员点下去拿到
403"角色不允许此操作"——按钮是摆设。

为什么之前的验收没发现：v0.3.0 的浏览器用例给题库测试用的是 `content` 账号、
给重试测试用的是 `technical` 账号，正好绕开了"只有 account_admin 角色"这条路径。

修复：复用接口的角色判定把 `account_admin` 视为满足任一 staff 角色。新增
`backend/tests/test_ops_admin_role.py` 三项回归，其中一项守住"不能顺手把门开大"
（没有匹配角色的工作人员仍然被拒）。

### 2.3 v0.3.2 —— 窄屏把返回路径藏了

`≤560px` 时 `.ops-crumb` 被 `display:none`，"返回家庭""返回报告列表"整条面包屑
消失。运营在手机上从儿童详情、报告详情退不回去，只能靠抽屉导航绕。

修复：改为换行展示，不再隐藏。

### 2.4 部署侧：运营后台必须在根路径 `/ops/`

Django 生成根绝对地址（重定向、`{% url %}`），带前缀剥离的 `/dingdong/` 入口只能
撑住第一次请求：页面一渲染，链接和重定向就跳到根路径。这和已有的 `/admin/`、
`/static/`、`/api/v1/` 是同一模式——上海 nginx 把运营后台自己的根路径转发给隧道。

占用根 `/ops/` 前核对过：上海站点 `/www/wwwroot/game` 没有 `ops` 目录，其
`index.html` 与 JS 资源也没有 `/ops` 引用，该路径此前只会返回原站的 SPA 兜底页。
验证原站未受影响：`/`、`/buddy/`、`/dinoworld/` 仍返回原内容。

### 3.1 公网浏览器验收覆盖

用例在 `frontend/deployment-tests/ops-public.spec.js`，指向
`http://110.42.225.196/ops/`，**不拦截任何接口响应**，凭据全部来自环境变量：

1. 登录失败有提示 → 成功进入工作首页 → 退出后无法直接访问受保护页面
2. 家庭按称呼查询（分页）→ 家庭详情 → 儿童详情，一页聚合成员、档案、活动记录、
   答卷、报告、关联与授权；详情页不出现 UUID
3. 题库：可视化新建草稿 → 未达标时发布被拦并给出可读原因 → 加题保存 → 发布 →
   已发布不可原地编辑 → 复制为新版本
4. 活动：维护目标、材料、备选方案、可展示风格与步骤 → 发布
5. 报告：查看已生成报告内容与生成状态；生成任务按"仅看问题"筛选，失败原因用
   业务语言说明并附系统代码，带权限判定重试且重复点击不再可点
6. 服务事项：按"待处理"筛选 → 详情 → 填写处理说明并完成 → 刷新后历史可见
7. 越权拦截：普通运营看不到"生成任务""账号与权限"，直接访问得 403，
   直接调接口也被服务端拒（403/404）
8. 窄屏（390×844）：展开抽屉导航、家庭列表可用；登录退出在抽屉内可完成

### 3.2 报告数据怎么来的（不是假数据）

公网演示库原本没有答卷、报告和生成任务。为了不"直接插入成品报告冒充闭环"，
本轮走的是真实链路：

1. 通过公网家长端 API 完成短信登录（固定码 `00000`）→ 建儿童档案 → 授权同意 →
   关联核验（`entry_proof` 为测试凭据）。
2. 用 `inject_fixture` 注入非生产测试输入（机器人观察、初始结果、渲染故障）。
3. 由 Beat（`schedule_due_syncs` / `dispatch_pending_reports`）与 Worker 真实跑出
   同步、阶段画像、报告任务与报告内容。

结果是 **2 份真实 ReportVersion**、1 个 `report` 任务成功、1 个处理中；其中的失败
任务是被真实注入的上游渲染故障打挂的，重试后由 Worker 重新渲染成功。

## 4. 受外部条件限制 / 未做

| 能力 | 现状 | 限制 |
| --- | --- | --- |
| 短信验证码 | 保留真实挑战、限频、消费、JWT 与权限流程 | 验证码固定为 `00000`，未接真实短信通道 |
| 伙伴数据同步 | 凭据核验、CA 主动同步、修订去重、授权撤回完整实现 | 数据来源是数据库 fixture，不是真实供应商联调 |
| 指纹采集 | 五张确定性合成 PNG，有界内存处理 | 不采集、不留存真实指纹 |
| 报告专业结论 | 展示真实答卷选择与题库来源 | 专业量表与评分解释待甲方确认，页面明确标注"未提供" |
| 运营账号数据分片 | 未做 | 后台是全量内部工具，不做按运营分片 |
| 移动端 App / 消息推送 | 未做 | 不在本次范围 |

**演示边界不变**：固定验证码、fixture 集成、不接真实供应商、不采集真实指纹。
后台账号密码与密钥不进仓库、不进测试证据、不进项目记忆。
