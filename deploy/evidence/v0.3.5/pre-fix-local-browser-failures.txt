# v0.3.5 修复前：新测试在旧代码上失败（本地 Docker 环境）

日期：2026-09-14
环境：本地 Docker 演示环境（镜像 dingdong-backend:0.3.4 / dingdong-web:0.3.4，即修复前代码）
入口：http://127.0.0.1:18473/（家长端在根路径，运营后台 /ops/）
命令：cd frontend && PUBLIC_HTTP_URL=http://127.0.0.1:18473/ \
      npx playwright test --config=playwright.public.config.js parent-conflict-recovery.spec.js --project=desktop

结论：4 项失败、1 项跳过（窄屏专项）。失败原因正是本轮要修的问题：
家长在旧表单上提交被判冲突后，前端立刻重建表单，家长填写的称呼被服务端值替换。

关键断言（第一条用例）：
    Expected: "冲突保留mu0ijhrp-家长改"
    Received: "冲突保留mu0ijhrp-运营改"

这说明"服务端没有被覆盖"是成立的（运营的值还在），但"家长未保存的输入被保留"不成立。
