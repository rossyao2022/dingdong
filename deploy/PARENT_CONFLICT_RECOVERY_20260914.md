## 2. 逐项修复

### 2.1 P2 —— 冲突后未保存输入被丢弃

**问题**（验收报告 P2，位置 `frontend/app.js` 的 `editChild`）：家长在旧表单上提交、服务端返回 `409 EDIT_CONFLICT` 后，前端立刻 `GET /api/v1/children/<id>` 并调用 `editChild(latest)`，**重建整个表单**。服务端保护有效（数据没被覆盖），但家长刚填写的称呼、性别、出生日期被服务端值直接替换，用户没有"载入最新"还是"保留我的修改"的选择机会。

**修复**：

- 命中 `409` 时**不再重建表单**：改为渲染一个独立的冲突提示区（`#child-conflict`），三个可编辑字段原样留在输入框里，只由家长自己决定下一步。
- 提示用家长能理解的语言："资料已被更新，本次修改没有保存……你填写的称呼、性别和出生日期仍留在上面的表单里"。**不出现 409 / 修订号 / 数据库**这类内部词。
- **三条显式路径**（缺一不可）：
  1. **查看最新资料** —— 面板里并排显示"我的填写（还没保存）"与"最新资料"三行对比表，**只读**，一个输入框都不动；
  2. **载入最新资料** —— 破坏性操作，先二次确认（明确写"无法找回"），确认后才用服务端内容替换输入框，并把基准修订号推进到最新，家长可在最新修订上继续编辑；
  3. **用我的修改保存** —— 先展示家长看到的那一版，再确认；提交基准取"家长看到的那一版"而不是刚读到的新版本，**这期间若又有人改过会再次被拒绝**，不会静默覆盖。
- **恢复期间再次变化**：再次冲突时提示升级为"资料又被更新了一次，本次修改仍未保存"，输入继续保留。
- **读取失败 / 断网 / 登录失效**（`0` / `401` / `403` / `404`）：只给家长语言的中文提示，**不清空输入、不显示保存成功**。
- **关闭对话框**：冲突未处理时先确认"你还有没有保存的修改"，避免新增一条丢失路径。
- 关闭对话框与保存成功时清空编辑会话状态，避免把上一份档案的过期修订号带到下一次编辑。

### 2.2 修正误导性测试

原 `frontend/deployment-tests/ops-p1-acceptance.spec.js` 中"运营改档后，家长旧页面保存必须报冲突并保留输入"一项，实际断言约在第 311 行变成"表单值等于运营的新值"，**测试名与实际验收目标不一致**。

- 该用例改名为"……且服务端保留运营的值"，**只断言服务端数据未被覆盖**（这是它真正能证明的事）。
- "输入是否保留"的断言迁到新增的 `parent-conflict-recovery.spec.js`，用真实业务目标断言。
- 两份 spec 共用的辅助函数抽到 `deployment-tests/helpers.js`，避免同一段登录/建档/检索逻辑分叉。

### 2.3 测试先红后绿（TDD）

先写准确的失败用例，在 **v0.3.4 旧代码**上确有多项失败（父端填写被服务端值替换、查看最新资料会把输入换掉等），日志见 [pre-fix-local-browser-failures.txt](evidence/v0.3.5/pre-fix-local-browser-failures.txt)；改完代码后全部通过。

### 2.4 同类缺陷排查

对家长端档案编辑会话做穷举，确认冲突相关的每条出口都有明确行为：

| 场景 | v0.3.5 行为 |
| --- | --- |
| 被 `409` 拒绝 | 保留输入，出冲突面板，不改表单 |
| 查看最新资料 | 只读对比，不动输入 |
| 载入最新资料 | 二次确认后才替换；取消保留输入 |
| 用我的修改保存（服务端未再变） | 以家长看到的版本为基准提交，成功 |
| 用我的修改保存（服务端又变） | 再次拒绝，输入保留，提示更新 |
| 读取最新资料失败 | 提示，输入保留，不显示成功 |
| 冲突未处理就关闭 | 先确认，不静默丢失 |
| 保存成功 / 关闭对话框 | 清空编辑会话，避免过期修订号复用 |

家长端其余写入口（答题、授权、服务申请）不涉及 `revision`，本次未改动。

### 2.5 回归测试

新增 `frontend/deployment-tests/parent-conflict-recovery.spec.js`（5 项，真实入口、不拦截任何接口）：

1. 冲突后家长的称呼、性别、生日全部保留，服务端仍是对方保存的值（并断言提示里不出现 `409` / `revision` / `修订号`）
2. 查看最新资料只做对比；取消保留输入；明确确认载入才替换表单，随后可保存成功、刷新可见
3. 恢复期间对方又改了一次：仍然拒绝覆盖、输入不丢、提示更新
4. 读取最新资料失败时：输入保留，不显示保存成功（唯一的人为模拟，用 `page.route` 让单个 GET 返回 503，属可控测试故障，注释已说明）
5. 窄屏下也能完成冲突恢复并保存

后端未改动业务代码，`backend/tests` 保持 237 项通过，其中含第三轮的 2 项独立复现用例。
