## 1 本轮确定的运行方式

短信登录统一固定验证码字符串 `00000`，不发真实短信。仍必须先发送挑战、验证有效期与错误次数、一次性消费、建立真实账号和 JWT；不能拿任意 challenge_id＋00000 直接登录。

其余所有 API 使用同一套正常路由、鉴权、参数校验、事务、业务服务和 PostgreSQL 查询。前端不拦截 fetch 返回假 JSON，后端视图不判断某个测试手机号便直接返回写死报告。

base 是必要基础数据；mock 是脚本注入的合成业务数据。尚无真实上游时，算法与 DingDong 适配器从独立的数据库测试数据源读取输入样本，由真实业务流程生成自己的观察、画像和报告。这部分是外部依赖的模拟，不能称为真实供应商联调；它不替换前后端 API。

配置 `SMS_MODE=fixed_code`、`INTEGRATION_DATA_SOURCE=database_fixture`，由部署环境选择，不由前端请求参数选择。生产配置拒绝这两种模式启动，避免日后忘记切换。当前无需短信服务商或真实机器人即可完成内部闭环测试。所有测试图片使用人工合成图，不采集真实指纹。

## 2 URL、认证与浏览器约定

根路径 `/api/v1`，同域部署。JSON 为 UTF-8、字段 snake_case。JSON 请求用 `Content-Type: application/json`，上传使用浏览器 FormData 自动生成的 multipart Content-Type，不手动写 boundary。

身份分三类：匿名登录相关接口；家长 JWT API；工作人员 Session API。后台页面仍用 Django Admin，只为发布、重试、启停等动作规定 `/api/v1/staff/...`，不再开发重复管理 CRUD。

首次打开调用 `GET /auth/csrf`，服务端设置 csrftoken Cookie 并返回 csrf_token。发送验证码、登录、刷新、退出及工作人员变更动作带 `X-CSRFToken`；刷新 Cookie 的 Path 为 `/api/v1/auth/`，浏览器 fetch 使用 `credentials: same-origin`。业务 API 带 `Authorization: Bearer <access_token>`。

refresh token 只存 HttpOnly Cookie，access token 在内存。刷新成功轮换刷新令牌且不延长首次 7 天期限；轮换响应 Max-Age 必须是剩余有效期，不能每次重置 604800。页面刷新先尝试 refresh，再读取 me；无有效凭据显示登录。

同一页面合并并发刷新；收到 401 只尝试一次刷新。GET 可以重试；创建动作保留原 request_id 后重试；图片提交不可自动重传。退出后清除当前页面数据、图片和摄像头，旧 grant 立即失效；后台 session 不接受家长 JWT。

正式 HTTP 部署使用 Secure Cookie；本机纯 HTTP 联调可由开发配置关闭 Secure，仅限本机。不因本机环境放弃 CSRF 或归属验证。

## 3 JSON 格式与字段规则

成功详情直接返回对象；分页返回 `{items,next_cursor}`；少量列表带 summary。无成功外壳 code=0；HTTP 状态承担成功/失败语义。无正文的 204 不调用 response.json()。

统一错误：

```json
{
  "code": "REVISION_CONFLICT",
  "message": "记录已更新，请刷新后重试",
  "field_errors": [{"field": "revision", "code": "stale", "message": "请使用最新版本"}],
  "trace_id": "99999999-9999-4999-8999-999999999999"
}
```

响应 `X-Request-ID` 与错误 trace_id 一致，普通访问日志只保留方法、路径模板、耗时、状态和追踪号，不记录验证码、JWT、上传正文。没有字段错误时 field_errors=[]。

未知请求字段拒绝，尤其不接收 family_id、owner、is_staff、grade、source、score 等可导致越权或伪造结果的字段。请求可选字段省略表示默认/不修改，null 表示明确清空可空字段；响应可空字段固定返回 null，不能用空字符串或 0 代替缺失。

UUID 示例只是格式。实际测试 ID 从初始化 manifest 获取，前端不能硬编码。手机号普通明文存储，统一国家码格式；姓名/称呼 1..80 字，性别 unknown/male/female，出生日期当前可空且不能晚于当前业务日期，不采集年级。最终算法年龄必填口径由 assessment-config 给出。

分页默认 page_size=20、上限 100，以稳定 `(created_at,id)` 顺序生成不透明游标；游标必须绑定查询筛选，不能拿其他筛选的游标混用。窗口参数 from/to 同时提供，带时区且 from<to，左闭右开。观察和总览必须提供窗口；活动列表窗口可同时省略。阶段窗口不支持时返回 422 WINDOW_UNSUPPORTED；不能静默改成 15/30 天。

## 4 幂等、并发与状态

创建儿童、授权、测评、活动、关联、处理事项，JSON 使用 `request_id`，数据库映射为 create_request_key。首次 201，重试返回 200 同资源；同键不同内容 409 IDEMPOTENCY_CONFLICT。现阶段只用此字段，不同时要求 Idempotency-Key 头。

撤回、取消、暂停、退出按目标状态幂等。活动 finish 同终态＋同反馈幂等，不同终态/反馈返回冲突。发布同一版本重复请求返回同一发布结果。后台重试使用目标 job 状态原子判断，不允许重复运行。

问卷/步骤使用 revision 乐观锁，过期 409；前端重新获取服务器数据后让用户确认继续，不用旧内容覆盖。PATCH answers 按题码合并：

```json
{
  "revision": 1,
  "answers": [
    {"question_code": "Q01", "option_codes": ["A"]},
    {"question_code": "Q02", "option_codes": []}
  ]
}
```

Q02 空数组代表清除答案，单选也使用数组。未知题码、重复题码、无效选项或超过 max_choices 返回 422。JSON 接口采用数组便于统一校验；数据库 assessment.answers 仍按题码保存映射，服务层负责转换。

一期实现单选/多选。M5 探索体验为 1–10 题（种子为参考四题），正式测评流程测试暂用 20–30 题（种子为22道日常情境题），不统一写死题量。正式题库如需要其他题型，必须扩展契约后再接入，不能将自由文本塞进选项 code。mock 不代表真实题量、维度或算法。

测评状态：draft→ready→processing→completed；失败可 needs_recapture，超时 result_unknown；取消 cancelled，过期 expired。unknown 不自动重传，技术侧先确认或关闭旧尝试；GET 会话返回图片之外的完整恢复数据。报告状态单独派生，测评 completed 不代表报告必然已生成。

活动状态：active→completed/skipped；step_index 从 0 开始，completed 要求已到最后步骤，跳过任意步骤均可；页面行为仍是自报，不宣称验证了线下实际活动。活动完成不更新专业画像或 DingDong 数值。

## 5 指纹提交的精确边界

`POST /assessments/{session_id}/submit` 为 multipart：request_id、revision，以及 slot_1..slot_5 五个文件字段。JSON 中不接收 base64。slot 名称只是内部五位置编码，具体手指含义由 input_requirements 返回；正式算法契约未确认，不先硬编码左右手映射。

fixture 配置只允许生成器规定的合成样例，collection_mode=synthetic_only；前端隐藏相机入口，测试使用合成图片。服务端也验证合成样例结构/内容，只关前端相机不算限制。此验证在内存完成，不保存图片或指纹哈希。

上传请求通过真实认证、授权、大小/格式/槽位、问卷完整性检查，再调用 fixture 数据源适配器；适配器只返回已注入的非生物结果样本。后续创建 attempt、profile、job 和报告由正式服务执行，不能直接复制一条预先完成的报告作为本次请求结果。

成功返回 200 SubmitResult；供应商/fixture 明确未知返回 202 SubmitResult，随后轮询 GET 会话。前置输入错误 422；已取消/重复不同提交等 409；调用明确失败 503 并保存安全状态。网络中断时前端先查询会话，不能判定无结果就自动重传。

测试单图 1 MiB、总图片 5 MiB 是合成用例限制，不是正式采集标准；请求总量限制另允许有限 multipart 开销。图片不进入 PostgreSQL、Redis、Celery、日志或持久临时文件。fixture 数据库也不例外。

## 6 结果、观察与报告的字段映射

| API 字段 | 数据库/服务来源 | 规则 |
| --- | --- | --- |
| user.phone_masked | app_user.phone 派生 | 不重复存脱敏号码 |
| questionnaire.questions | questionnaire_version.questions | 固定版本，不拿当前新题库覆盖旧会话 |
| assessment.answers | assessment_session.answers 转数组 | 参数与数据库结构通过服务转换 |
| activity.steps/allowed_styles | activity_content_version.content | 旧记录仍读旧版本 |
| activity_record.activity | activity_version FK 展开 | 不依赖前端当前硬编码活动 |
| observations.metrics | observation_batch.payload 规范化映射 | 指标 code、label、value、unit 明确；无值 null |
| profile.metrics | profile_snapshot.result 规范化映射 | 非生物业务结果；按 schema_version 校验 |
| report.sections | report_version.content 的 sections | 纯文本结构，不执行 HTML |
| report_status/stage_status | 对应 job、profile、report 联查 | 无需为每种展示状态建新表 |
| data_origin | 内容/观察/画像/报告的数据来源标记 | synthetic/live，不能把合成数据伪装成真实结果 |
| source=dingdong | 数据语义来源 | 与 data_origin 分开：可以是“模拟 DingDong 数据” |

真实字段尚未确认的 metrics 使用明确的通用展示模型，不写死 companion/wisdom 等供应商维度。data_origin 在自有版本内容、观察、画像和报告增加字段；API 活动记录可从活动版本派生、会话从题库派生。处理链输出只要任一来源为 synthetic，结果必须 synthetic；不混合不同来源生成伪装 live 的报告。

趋势只有同维度、同单位、兼容规则和可比较窗口才计算；delta=current-previous，否则 available=false＋reason。前端不自行拼取多个接口后相减。current_window、previous_window 为 null 时 changes 必须为空。

服务事项删除完成后，GET /children/{id}/data-requests 不足以查询已删除孩子的回执。本版增补家长级 GET /data-requests（见 OpenAPI）：按 requester_id 查询去标识化的回执；完成删除时清空可空的 child_id 关联，不保留已删除姓名/正文。数据库 data_request.child_id 原本可空，API 同步为 nullable。家长账号删除暂不在一期此接口范围内。

## 7 主要错误码与前端动作

| HTTP | code | 前端处理 |
| --- | --- | --- |
| 400 | INVALID_JSON | 修复请求格式，不重试 |
| 401 | AUTH_REQUIRED / TOKEN_EXPIRED / LOGIN_REVOKED | 仅尝试一次刷新，失败返回登录 |
| 403 | CONSENT_REQUIRED / PERMISSION_DENIED | 展示对应授权或无权限提示，不循环请求 |
| 404 | NOT_FOUND | 不泄露其他家庭对象存在性 |
| 409 | REVISION_CONFLICT | 重新读取，提示内容已更新 |
| 409 | IDEMPOTENCY_CONFLICT / STATE_CONFLICT / ACTIVE_ACTIVITY_EXISTS | 保留当前对象状态，提供继续已有活动等动作 |
| 422 | VALIDATION_ERROR / ANSWERS_INCOMPLETE / INPUT_SLOTS_INVALID / WINDOW_UNSUPPORTED | 根据 field_errors 定位输入 |
| 422 | SMS_CODE_INVALID / SMS_CHALLENGE_EXPIRED / SMS_CHALLENGE_USED | 提示验证码错误或重新获取，绝不自动重发短信 |
| 429 | RATE_LIMITED | 按 Retry-After 秒倒计时 |
| 503 | INTEGRATION_NOT_READY / UPSTREAM_UNAVAILABLE / CONFIG_NOT_READY | 保留问卷及状态，提示稍后处理；不把失败置零 |

SMS 挑战达到 5 次失败后 locked，再提交 00000 也不能成功。字段 code 使用字符串五位；正式短信模式接入前另确认位数，不通过自动转数字处理。

服务端未预期错误使用 500 INTERNAL_ERROR＋trace_id，不向客户端暴露堆栈。已知延迟状态使用 202，并非 HTTP 错误。轮询建议前台每 2 秒开始，渐增到 5 秒，最长 60 秒后停止并提示稍后刷新；没有新状态时不持续后台无限轮询。

## 8 三条可执行交互顺序（API 实现后）

### 新用户与网页活动

GET runtime/csrf→POST sms(phone)→POST login(challenge_id,"00000")→POST children(request_id,name)→GET activities→POST activity-records→PATCH 步骤直至最后→POST finish→GET activity-records / growth-overview。完成次数只增加一次，换浏览器登录仍可见，其他家庭请求同 record_id 为 404。

### 新测评与报告

获取并同意 assessment_processing→GET assessment-config→POST assessments→逐题 PATCH answers→POST submit（合成文件）→GET assessment 直到 report_status=ready→GET reports/{report_id}。实际调用报告 worker，不能只读 seeded completed report 来代替这条测试。

### 新关联与阶段报告

同意 dingdong_sync→POST associations/verify（种子数据中的测试票据）→实际调度同步 job→适配器读取数据库 fixture 观察→业务服务写观察并推进 checkpoint→测试规则生成 stage profile→worker 生成报告→GET growth-overview。技术人员暂停/恢复或重试用 staff Session API，不能用家长 JWT。撤回授权后，再注入新的 fixture 批次，执行同步也不得写新业务观察。

## M4 实现补充：恢复测评会话

新增 `GET /api/v1/children/{child_id}/assessments`（家长 JWT），查询参数 `page_size`、`cursor` 与通用分页约定一致。返回 `{items: AssessmentSession[], next_cursor: string|null}`，会话内含固定题库 questions、已保存 answers、revision、missing_question_codes、处理及报告状态；每个字段与原 GET assessments/{session_id} 的同名字段定义一致，以 OpenAPI 的 Assessments/Assessment 为准。空列表为 `{ "items": [], "next_cursor": null }`。未认证返回 401，其他家庭儿童返回 404。

前端以此查找未结束的会话，重新登录后从服务端取回题目和答案，不在浏览器持久保存答案。M4 时共49个操作；M5增加探索完成接口后为50个操作。


## M5 题库用途与探索完成契约

- GET `/assessment-config?purpose=exploration|assessment`，默认 assessment。可附 `questionnaire_version_id` 选择目录中的发布版本；无效用途/UUID 为422，不存在或停用版本为404。返回 `purpose/title/description/version` 和 `questionnaires` 目录（id、code、purpose、title、description、version、question_count）。默认分别优先 initial-assessment/exploration code；其他题库在家长端单独显示。
- 答卷追加 `purpose/questionnaire_code/title/description/version/choice_summary`。所有内容取创建时固定 FK；发布新版本不替换既有 FK。`choice_summary` 仅完成的探索返回，包含原题干与所选选项文字；无专业评分。
- POST `/assessments/{session_id}/complete-exploration`，JSON `{ "revision": 2 }`；返回200 Assessment。相同版本重复完成返回同一答卷。未答必填为422，版本冲突或取消/过期为409，跨家庭404，授权撤回403。探索不得使用图片 submit；此完成入口不能用于正式测评流程。
- 后台 Django Admin 的逐题表单存储 questions JSON 是内部实现，运营无需编辑 JSON。复制入口 `POST /admin/core/questionnaireversion/{id}/copy/` 使用 Django Session + CSRF + content 权限；发布沿用 staff publish API。
- 新报告选择摘要来自答卷；数据库外部测试输入只表明专业结果未提供，不注入天赋分数。旧报告不追溯覆盖。
