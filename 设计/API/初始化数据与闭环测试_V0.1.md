# base / mock 初始化与一期闭环测试设计

> 2026-09-12 实施更新：下文早期方案若与此说明冲突，以本段为准。seed_base、seed_mock、inject_fixture 已实现；不存在 reset_mock。seed_mock 提供四题体验、22道可读测试题和8个可执行活动，以新版本替换已知占位种子，保留旧答卷/报告。warm 仅为输入初始化兼容别名，不再创建成品业务结果。所有活动完成、体验完成、报告与回执通过真实 API/Worker 流程生成。当前运行说明见 backend/README.md，验收见 backend/docs/M5_RESULT.md。

用户约定：短信固定 00000；其他 API 不 mock，使用真实后端和数据库初始化/注入的数据。本文件说明当前初始化命令、输入数据边界和验证流程。Django 工程已实现，并已通过真实数据库/浏览器测试。

## 1 两层数据

### base：可重复初始化的系统基础

- Django Groups：operations、content、technical、account_admin；固定权限集合。
- 必要内容 code、系统状态和默认配置。正式授权说明/题库/规则未确认时不预置“已认可”的正式版本；界面应能显示未配置。
- 不创建真实家庭、孩子、画像、报告；不创建通用默认超级管理员密码。工作人员由单独初始化步骤创建，凭据从运行环境注入。
- 以 code/version 为自然键幂等 upsert；第二次执行不重复建角色、不覆盖工作人员自行维护的已发布业务内容。

### mock：合成业务数据和外部数据源样例

- 两个家长测试账号/家庭，用于跨家庭权限验证；短信无需保存验证码明文，只在 fixed_code 模式实际创建挑战时验证 00000。
- 多个合成儿童，姓名均显式测试用途，不采集年级。一个家庭可有多个测试孩子，配合已有模型。
- 两份测试用途说明、四道原参考探索题、22道日常情境测试题、8 项待测活动、测试报告模板、规则 code=`test_rule_v1`。发布状态仅表示测试环境可使用，不能对外称专业题库或真实算法。
- 数据库 fixture 数据源：一次性合成核验票据；按测试儿童绑定的算法成功/失败样本；机器人批次、窗口、版本、缺失值与故障样本。
- 页面覆盖数据：待答题、待重采、未知结果、初始报告、活动完成/跳过、同步失败/缺失、阶段报告、服务事项等状态。
- data_origin=synthetic 从输入内容传递到观察/画像/报告，前端显示合成数据标记。

mock 不包含指纹图片、base64 或生物特征模板。合成图片单独由测试进程即时生成，上传后释放，不作为数据库 fixture 保存。

## 2 两种用例数据集，不能互相替代

**cold 数据集**：账号、儿童、授权说明、发布内容、外部 fixture 输入齐备；不提前生成被测 session/profile/report。用真实 API 从零创建活动和测评，用真实 worker 生成画像与报告，验证全部写入和状态转换。

**warm 参数**：M5 起仅作为输入初始化的兼容别名，不预先建立已完成业务对象。页面状态必须通过真实业务流程准备。

测试重新开始时按 seed manifest 仅清理本次数据集拥有的对象，遵循 FK 依赖；不要 truncate 整个数据库。mock 默认拒绝 production。全库清空不属于初始化命令默认能力。

## 3 当前可运行命令

在 backend 目录中通过 `uv run` 执行以下命令：

```sh
python manage.py seed_base
python manage.py seed_mock --dataset phase1-v1 --mode cold
python manage.py seed_mock --dataset phase1-v1 --mode warm
python manage.py inject_fixture --dataset phase1-v1 --child-id <UUID> --scenario sync_correction
```

- seed_base：事务创建/复用四个固定角色，按当前代码同步权限，输出角色与范围；不创建默认管理员。
- seed_mock：只支持非生产 phase1-v1；确定性ID/自然键复用记录。已知占位种子通过 readable-v2 升级，旧发布记录停用但不改写内容；运营自行发布内容不覆盖。warm 与 cold 均只创建输入，不存在 dataset_run 实体。
- inject_fixture：写入指定孩子的外部样本/故障场景，随后等待/触发正常任务执行；不直接更新 API 返回缓存，不直接把 job 改成功。
- 未实现 reset_mock。隔离测试使用 pytest 测试库或独立开发数据库，不提供默认全库清空命令。
- seed_mock 输出 dataset、mode、data_origin、测试用户/家庭/儿童ID、活动ID和创建/复用统计。inject_fixture 按场景输出输入状态或测试凭据；具体以命令 stdout 为准。没有固定 now/dataset_run 清理平台。

短信请求仍由 API 产生 challenge，manifest 不提供绕过验证的现成 token。文档和 OpenAPI 中重复的示例 UUID 不是 seed 主键，测试使用 manifest。

## 4 最小测试数据源结构

仅 development/test 安装测试支持 app。可以使用一张 `test_fixture` 表：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| id | UUID | 主键 |
| dataset | varchar(64) | 数据集名称/版本 |
| kind | varchar(32) | identity / initial_result / observation / fault |
| subject_key | varchar(128) | 关联测试 child ID 或种子身份，不暴露为家长 API 控制参数 |
| sequence | integer | 确定顺序，默认 1 |
| payload | JSONB | 按 kind 验证的合成内容，只允许测试非生物业务字段 |
| consumed_at | timestamptz? | 一次性 identity 票据消费；观察不通过消费标记代替业务去重 |

唯一 `(dataset,kind,subject_key,sequence)`。payload 的 kind 结构固定在测试模块：identity 包含绑定对象与 TEST-PROOF；initial_result 包含 schema/version/测试 metrics；observation 包含窗口、logical_key、revision 与测试指标；fault 只允许特定错误 code 和适用调用次数。

故障控制不能成为生产客户端可调用的 API，不接收 `?mock=true` 或任意 scenario 字段。初始结果 fixture 绑定到测试儿童和题库版本，新测评提交后真实校验答案/上传，再读取该样本。没有匹配样本返回明确的 FIXTURE_NOT_FOUND（非生产配置错误），不随机生成结果。

fixture 模式不判断真实指纹，不对样本图计算专业分数。测试 stage rule 使用明确标为合成的确定性计算（例如同窗口 test_count 求和），仅验证输入选择、幂等、版本及报告渲染，不能拿它充当正式成长评分方法。

新建 child 后需测试外部流程时，由测试运行器通过 inject_fixture 按返回的 child_id 注入数据；不得在生产创建档案服务中偷偷生成测试机器人或算法样本。

## 5 场景矩阵

| 场景 | 注入内容 | 必须走的真实动作 | 预期 |
| --- | --- | --- | --- |
| fresh | 基础发布内容、无业务结果 | login→create child→读取总览 | 正确空态，无假 0 分 |
| sms_invalid | 不需额外注入 | 先 sms，再输入错误码/00000/重复码 | 错误累计、正确一次消费、重复拒绝 |
| family_isolation | A/B 两个家庭各自记录 | B 请求 A 的 child/record/report | 404，无字段泄露 |
| activity_complete | 发布活动 | start→步骤→finish×2→查询 | 同一记录、完成数只增 1 |
| activity_skip | 发布活动 | start→skip→再次完成 | 跳过无分数，冲突操作 409 |
| assessment_success | 合成题库＋初始结果源 | 新 session→答案→合成上传→worker | 新 profile/report，完整来源，synthetic |
| assessment_bad_input | 缺题/缺槽位/无效图片 | submit | 422，无成功画像，不保存图片 |
| assessment_timeout | initial_result 的超时故障 | submit→轮询→后续明确处理 | unknown，不能自动重传或生成假结果 |
| sync_success | TEST-PROOF＋观察样本 | 授权→verify→真实同步任务 | verified、观察入库、checkpoint 前进 |
| sync_duplicate | 相同 logical_key/version/content 两份 | 连续同步 | 不重复计数、不重复阶段报告 |
| sync_correction | 同语义窗口新版本合法修订 | 同步→评分→报告 | 新修订引用新来源，旧报告可追溯 |
| sync_conflict | 同上游版本不同内容 | 同步 | 明确冲突，不覆盖旧成功数据 |
| sync_failure | 先成功数据，再超时故障 | 同步 | 旧值标 stale，checkpoint 不前进 |
| no_consent | 已关联但撤回授权，另注入新批次 | sync worker | 不新增观察/画像，显示 no_consent |
| rule_missing | 观察齐备，测试规则未发布 | stage job | waiting_rule，仍可看行为观察 |
| rule_version | 两个测试规则版本 | 发布新规则→新任务 | 新画像/报告，旧内容不变；不乱算跨版本趋势 |
| report_retry | 报告生成一次受控失败 | staff retry→worker | 从 failed 恢复，成功结果不重复 |
| permission | 三类业务角色＋账号管理员 | staff 发布/重试/改角色 | 对应允许/拒绝；家长 token 不可进入 |
| deletion | 合成儿童含报告/活动 | 创建事项→实际处理→家长查询回执 | 数据按范围清理；可读去标识回执，不只改状态 |

日期固定到 manifest 的 test window。统计按 Asia/Shanghai；测试时显式注入时间基准，避免明天运行就过期。JWT、验证码的有效期测试使用可控时钟或测试工具推进，不把过期检查去掉。

## 6 验证范围

全部 API 对数据库实际状态作断言：行数、唯一键、来源 FK、任务完成、授权撤回和最后同步窗口。捕获前后端请求，确认无 fetch mock/假路由，并对真实进程重启后的持久性、任务恢复做测试。

参考演示 localStorage 不自动迁入；活动计数与报告以数据库为准。从输入初始化出发，经过真实 API/Worker 创建页面所需状态，作为内部闭环验收。真实供应商字段、图片处理质量与线上设备链路仍须另行联调，数据库样例不能替代该部分验证。
