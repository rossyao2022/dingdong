# 家长体验主线与 CA 数据交接方案

日期：2026-10-01。状态：**调查及建议方案，待用户评审；未改功能、未提交对方、未部署**。v0.3.24 的既有功能和历史保留。依据：用户本轮全部困惑、当前代码、对方 2026-09-22 两份对接 docx/code 表；不以早期“无推送”设计替代后续已实现 webhook 的事实。

## 1. 核心问题与当前事实

产品目前按功能和数据来源组织，而家长需要知道“发现了什么 → 今天怎么陪 → 做完有什么变化”。只合并同名按钮、加日期，会改善查找，不能补齐这个价值链。

| 当前数据/功能 | 已实现 | 尚未成立的关系 |
| --- | --- | --- |
| 六岛兴趣 | 六选三、9 个情境，所选三类喜欢程度均值 0–4，儿童级真实保存 | RIASEC 六类不是 DingDong 六个人设兴趣 code；没答的三类没有测量 |
| 八维日常观察 | 24 题，每维三题累计 3–15，保留题目/原始回答与版本 | 不是对方正式画像所需的专业八维原始 0–100 分；不能直接拉伸成专业分 |
| 四情境与网页陪伴方式 | 四类回答计数，cognitive/imitative/reverse/open；网页引导偏好可手选 | 不等于经双方确认的学习风格评估；9月22日 code 表与当前线上 OpenAPI 枚举不一致（CA 用 imitative，线上用 imitation 且含 reverse），偏好也不是性格 |
| 22 题初始报告 | 真实问卷、提交及 Worker 生成报告，回看本次回答 | 当前专业测评结果为 null；不能称专业能力诊断 |
| CA 活动/职业小项目 | 已有实际活动、步骤、感受、历史与小项目 | 未形成一条可恢复的统一任务主线；部分推荐文案没有贯通到实际活动记录 |
| DingDong 报告 | 生产可拉取 shared Prototype insights；有验签/处理入口，已有快照可展示 | 共享 Mock/模拟趋势不能算当前儿童真实成长，也不能证明 CA 问卷改变了伙伴；最近生产核验事件仍 0、4 快照均 pull |
| CA → DingDong | generic 出站传输存在，已用于绑定、查询和复测操作 | 没有 profile payload 构造、字段映射、自动上传、Cookie 测评提交或跨站会话交接 |

本轮另只读取得[对方当前 OpenAPI 核对](../.trellis/tasks/09-30-prototype-content-integration/research/ca-report-live-contract-20261001.json)：正式学习风格为 cognitive/imitation/reverse/open，Prototype 只必填 interest_primary，学习风格默认 open、性格偏好默认 either。它与 9月22日三值 code 表有差异，需确认当前权威取值；默认值不能被包装成测评结论。

独立证据见[接口复核](../.trellis/tasks/09-30-prototype-content-integration/research/v0324-ca-profile-contract-review.md)。`frontend/app.js` 当前测评用途明确“报告保存在你的账户中，不会发送给机器人”，绑定后的读取授权不等于允许上传新的测评资料。

## 2. 家长主线：发现一件事，试一次，留一个发现

保留登录 → 儿童建档 → CA 探索，不改为先聊天；原导航和全部探索模块保留。首页增加一个主任务区，每个状态只突出一个主要动作，其他功能自由进入。

| 当前儿童状态 | 主页面给家长的提示 | 唯一主动作 |
| --- | --- | --- |
| 首次建档、无探索 | 先看看孩子对什么感兴趣 | 开始兴趣探索 |
| 有未完成探索 | 上次的探索还没做完 | 继续上次探索 |
| 完成探索、未做小行动 | 根据本次回答，选一个可以一起试的小行动 | 开始这次小行动 |
| 小行动进行中 | 已保存到当前步骤 | 继续这个活动 |
| 小行动完成、未留感受 | 孩子喜欢吗，还想试吗 | 留下一句话/选择感受 |
| 已完成一轮 | 显示这次真实完成与记录，下次可以继续或换个尝试 | 下一次小行动 |

“游戏感”来自阶段进度、明确下一步、完成反馈与回来能接着做。进度表示任务完成，不表示孩子能力或天赋等级。用户随时可以离开主线、换探索或跳过推荐；中途回答、活动步骤、返回后的进度按儿童保存。

兴趣、八维、指纹、职业认识的定位：兴趣是第一轮推荐入口；八维是进一步日常观察；指纹是趣味知识支线，不能产生学习/天赋画像；职业用于打开认识和小项目，不导出为职业适配结论。22 题问卷入口和历史保留，当前不强迫每位新用户先做完全部问卷；是否作为正式测评主线需 CA 业务给出专业用途。

活动承接必须关联已发布的真实 ActivityContentVersion 和儿童 ActivityRecord。建立可解释的规则表；找不到匹配活动时让家长选，不生成不存在的推荐。下一步具体行动由已保存回答/家长选择/活动状态决定，不能只写泛泛的鼓励话。

## 3. 报告先告诉家长用途，再给细节

报告主页面首屏应回答：

1. **这次发现了什么**：基于某次真实回答、说明适用范围，不给固定能力标签。
2. **今天可以一起做什么**：一项实际可打开的小行动；已有机器人且支持个人同步时可承接经确认的机器人活动。
3. **做完看看什么**：喜欢程度、是否愿意继续、一个真实行为或一句发现。

例如，只在实际记录支持时写“这次所选的三个方向中，孩子对动手活动更感兴趣”，不能写“孩子的工程天赋已确定”。未完成、并列或无差异时据实显示，不强行排出优势。

下方统一“探索与测评记录”，按完成时间新到旧排列：兴趣探索、八维观察、探索问卷、日常情境问卷；名称/时间/状态区分每一条。相同问卷和其生成的报告合为一次记录，展开再看回答/结果；生成延迟不改变体验完成时间。已有报告保留且详情标题使用实际问卷名。

**建议调整刚上线的全量报表主页面呈现**：首屏先是发现与下一步，完整 DingDong 原表/模拟曲线放在“查看详细报告”中，完整数据不删。需本次方案评审后实施，不能把该建议说成已上线。

CA 与机器人在用户心中的关系应是：探索提供一次陪伴线索，实际活动或机器人对话提供体验机会，回看真实记录帮助选择下一次尝试。现在这条个人数据关系没有实现，不能提前展示“机器人已按本次测评定制”。

共享 Prototype 必须作为独立体验，不能把共享伙伴/模拟曲线写进孩子的个人结论，不能与 CA 原始分加权生成统一成长分，也不能用模拟上涨声称干预有效。展会体验不改变孩子已经完成的 CA 主线。

## 4. 对方的“报告表单”是什么，今天可以提供什么

根据原话“最后生成报告呈现的内容…测评完的报告表单…能同步的部分…方便对”，合理推断对方在核对 **CA 实际输出的数据结构及可接收字段**，并非确定要求某份空白调查表。其确切意图仍需对方确认。我们应一次提供三个互相对应的东西：

- 一份报告/结果页面样稿，展示家长实际看到什么；标明真实记录还是合成样例。
- 一份结构化 JSON，含本次记录、完成时间、题库/计分版本、结果及缺值，不混入所有家庭历史。
- 一份中文字段对照表，逐项标明 CA 当前有无、单位/范围、对方字段、映射是否确认。

已准备[字段交接说明](联调样例/20261001/CA报告字段交接说明.md)和[合成结构样例](联调样例/20261001/CA报告结构化样例_合成.json)。样例原始答案为显式合成输入，结果由当前真实 compute_result 算法计算，不使用真实家长资料，不填造专业分；这是待核对的资料包格式，**不是已上线的 API 或可直接提交的 /profile 请求**。

对方未见我们的输出、我们又没有稳定的上行 DTO/字段导出，导致日常联调靠人工解释。这是长期能力缺口，应做成常规后台能力。

## 5. 两条实际接口路径，不能混为一条

### 5.1 当前展会 Prototype

对方文档的测评切换为 `POST /api/v1/app/companion/prototype/assessment`，使用 **DingDong 网页 Prototype Session Cookie**，只收 `interest_primary`、`learning_style`、`personality_preference`。对方根据这些选择生成 Mock baseline；它不接收我们当前八维原始观察分。正式 `/api/v1/ca/profile` 在 Prototype 下不能覆盖固定 Mock 画像。

因此不能让 CA 后端拿 X-API-Key 直接照搬浏览器 Cookie 调用，也不能自行假设其已有跨域授权。需 DingDong 提供适合 CA 后端调用的正式说明或新增 X-API-Key 鉴权的演示交接接口；另一可选路径是签名的一次性交接机制，由对方网页验证并建立/使用其会话。具体路径由双方确认，不擅自把个人 Cookie 放进服务器。

展会数据为共享状态，不能每位游客一答完就自动改 `ca_dingdong`，影响其他人。第一阶段先用工作人员明确选定的一份演示样例，预览字段、确认应用范围后更新一次；普通游客仍完成自己的 CA 记录及可选共享体验。演示选择、CA 原始回答与对方 Mock 八维必须分开保存和说明。

### 5.2 后续个人机器人

对方正式契约为 `POST /api/v1/ca/profile`，X-API-Key 仅放 CA 后端。需实现版本化映射和可审计的发送记录，至少包含：个人机器人对应账号、assessment/profile ID、完成时间、学习风格、主/次兴趣、八维专业分或 null、profile_version。

发送前须已确定目标账号、有效绑定、上传用途授权、合法映射及资料版本；不具备时留在待核对状态，不伪称同步成功。当前只能可靠发送的字段组合、必填 learning_style 的缺值处理，以及全 null 八维是否有用，均须 DingDong 确认。CA 不自行把观察分转为专业分。 若双方认为当前观察数据有用，可以另外约定原始量纲的观察字段或扩展接口；不要求所有有用数据都先变成专业分。正式八维专业字段则只填符合其定义的结果。

发送用后台队列/outbox，保存 request_id、payload 摘要、映射版本、目标账号、响应及时间；超时查询或重试使用同一键，不重复制造新画像。发送前后核验绑定仍是同一账号、源记录未被替代，避免解绑后写入错误用户。区分已受理与已应用，以对方 profile_id/回读确认实际应用。新记录不覆盖旧报告、不自动换伙伴；选择伙伴仍由家长确认。

新增个人上行前须调整具体数据用途说明并取得该用途授权。当前明确“不发送给机器人”的授权不能被静默重新解释。

## 6. 后台常态功能

在儿童的**某一份**答卷/报告详情增加“对接资料”，而非让运营在整库中拼数据：

| 能力 | 内容与作用 |
| --- | --- |
| 预览交接字段 | 中文字段、实际值、范围/单位、来源记录、版本、对方字段、缺失/待映射原因 |
| 复制联调摘要 | 脱敏说明与字段对照，可直接发技术同事；不含手机号、照片、NFC 凭据或密钥 |
| 下载 JSON | 当前选定记录的稳定结构化包，默认仅所需输出字段；原始答案作为另受权限控制的调试导出 |
| 查看可同步状态 | 待映射/缺字段/待授权/目标不确定/待发送/已受理/已应用/失败；显示负责方和处理办法 |
| 提交/重试 | 双方路径确认并满足条件后才开放，记录目标、来源版本与审计；仅导出不自动上传 |

复制/下载和实际发送应复用**同一份保存的数据快照与 DTO**，避免人工 JSON 与真正请求不同。展会资料与个人正式资料明确不同数据性质；运营可复制必要脱敏摘要，技术或授权岗位才可取完整调试字段，按现有权限扩展且有审计。

家长现有“导出此记录”是儿童探索/活动/网页偏好归档，当前不含 22 题报告、profile 或机器人报告，也不是上述对方交接 DTO。保留原能力，新增用途明确的后台交接功能。

## 7. 分工、顺序与验收

| 负责方 | 需给出的具体支持 |
| --- | --- |
| 我方 CA 开发 | 主线状态与一项真实行动的贯通、结果摘要及记录列表；稳定交接 DTO/版本/缺值、后台预览复制导出；双方确认后做发送队列/回执/绑定和授权保护 |
| DingDong 开发 | 核对资料包实际能接哪些字段；Prototype 后端交接鉴权/地址/必填/回执；确认提交是否重置伙伴或成长数据及共享冲突；线上 OpenAPI 与 code 表的学习枚举差异、null 分数语义、幂等及已应用证明 |
| CA 业务人员 | 各问卷实际用途与可对外的结论；兴趣/学习/八维到对方字段的合法映射与缺值/并列规则；活动推荐表、报告白话和现场演示样例；专业评分供应方/规则何时可提供 |

顺序：

1. **先对齐真实输出和用户价值**：本方案及交接样例供用户/双方评审，保持当前线上。
2. **先做不依赖对方的主线和交接导出**：登录建档不变，兴趣 → 实际活动 → 留感受；报告先给发现与行动、日期记录可回看；导出不可用的字段明确缺失。
3. **经确认后接通有限的展会交接**：工作人员样例 → 对方实际应用 → 返回同一方向/源版本，不能以 HTTP 200 或一张共享报表替代闭环证据。
4. **有业务映射和真实个人账号后扩展正式同步**：有效个人目标/授权/幂等/历史/重试/撤权及晚响应边界。

验收重点：首次家长不用工作人员讲解就知道下一步；中断重进恢复正确孩子的任务；没机器人也能完整走一轮；看完结果能打开一个真实小行动；同一次记录只出现一次且带实际完成时间；不同来源没有混算或假个性化；复制/下载/实际发送逐字段一致；缺分、并列、未知枚举拒绝凑数据；共享账号不被每个游客自动改写；双方用记录 ID、映射版本和回执证明同一份资料被应用。移动 E2E/原模块回归/手册与发布仍按仓库流程执行。

本方案不将专业算法、正式设备接入或对方自动推送标成已完成，也不因页面有很多模块就宣称主线已经贯通。
