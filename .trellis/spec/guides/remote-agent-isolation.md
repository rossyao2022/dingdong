# 远程设备代理隔离与验收

2026-10-01，来自生产机Remote Desktop Commander安装实证。

- 任意命令工具的目录/命令配置是误操作提醒，不能作为安全边界；独立非root容器，只挂批准目录，不挂Docker socket/主机PID/密钥/业务数据。主机只读观察用不含参数或环境的专用摘要，不给终止业务进程权限。
- 不盲用root设备代理。状态凭据属于代理自己的授权身份，授权终端用户同UID可访问，不能声称目录白名单隔离了它。对主机其他账户用0700/0600保护，不读凭据内容作验证。
- 固定官方npm包与依赖lock、核对官方发布校验值。跳过安装脚本后验证真实二进制/工具，不把npm退出0当全部功能可用。
- 复制Node发布包时保留npm/npx符号链接；若复制工具解引用链接，镜像中按官方布局恢复，不升级主机Node。
- 复用镜像要取消继承healthcheck、移除应用副本，注意Docker旧WORKDIR可能重新创建空目录；最终状态用真实容器检查。不能改变原业务镜像或主机文件。
- systemd账户需要实际可解析的专用不可登录账户；数值UID没有对应主机用户时可能217/USER。不能用root绕过；文件可写范围精确指定。
- 临时下载通道只监听回环、限定官方源并保留TLS/签名验证，关闭后核对本地和服务器监听端口消失；不擅改SSH或防火墙核心规则。
- service enabled不是实际整机重启测试；不为验收擅自重启生产机。本地stdio工具验证、设备ready、持久授权重启、ChatGPT OAuth及远程调用必须逐项分开记录。
