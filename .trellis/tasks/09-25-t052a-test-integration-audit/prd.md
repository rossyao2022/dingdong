# T-052A 测试与联调缺口核查

## Goal

用可重复的测试与实测证据判断项目还差什么，并修复我方可以确认的契约适配和回归脚本问题。

## Requirements

- 跑后端测试与覆盖率、前端单测、浏览器回归、静态检查、迁移检查、部署脚本测试和文档审计。
- 区分真实业务故障与历史验收脚本状态失效。
- 对人设扁平响应加入回归用例并修复适配，保留嵌套夹具兼容。
- 将 T-030 两阶段历史脚本改为显式启用；修正依赖共享数据库顺序和错误轮询假设的浏览器断言。
- 记录上游待提供或确认的能力、凭据与正式契约，不把这些标为已通过。
- 逐项复核 T-050/T-051：固定账号与 NFC 绑定语义、正式账号 ID、测评切换入口、四个展示子接口与 insights、configure 枚举、聊天陪伴值、真实 webhook 推送、分数类型。

## Acceptance Criteria

- [ ] 真源模式处理实测扁平数据时返回可显示的人设及绑定时间/匹配度；原嵌套夹具不退化。
- [ ] 不指定 T-030 阶段时，全量回归不执行一次性历史验收；显式阶段仍可运行。
- [ ] P-16 验证对话框在轮询间隔内保持打开，关闭后恢复待处理刷新。
- [ ] 测试总结列出通过/失败/跳过数、覆盖率、已知供应商缺口和真源未完成条件。
- [ ] 联调结论明确区分我方 webhook 公网冒烟成功与供应商真实 milestone 推送到达；不以其一替代其二。

## Out of Scope

- 供应商 `growth/profile`、`persona/health`、真实推送或正式 NFC 校验的服务器实现。
- 把本地 `synthetic_fixture` 直接改为生产真源或改动生产配置。
