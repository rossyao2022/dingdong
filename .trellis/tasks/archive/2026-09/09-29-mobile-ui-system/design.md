# 设计

## 现状与取舍

家长端为原生 JavaScript 模板字符串，`styles.css` 与 `playful.css` 保留参考视觉，项目覆盖写在 `client.css`。当前缺少页面层的统一纵向节奏，`#reports` 把 `.grid`、单面板和空态直接串接，导致边界相贴。移动表单和导航沿用桌面尺寸，在 320px 下挤压或折行。

选用开发期 `@storybook/html-vite`，不把 React/Vue 或三方运行时组件塞进家长端。抽出少量现有 HTML 构件到原生 ES 模块，供 `app.js` 与 stories 共同调用；Storybook 引入现有三份 CSS。用 Vite builder 只服务开发预览，生产发布仍直接加载原生 JS/CSS。

## 布局规则

- 报告页内容增加一个专用的 `report-flow` 容器，使用统一列间距；标题及表单在容器中与卡片遵循同一间距，取消零散的行内 margin。
- 表单在手机端的验证码区、时间窗区按单列排布，字段及提交按钮占满可用宽度。卡片的直接操作按钮与正文之间用统一间距。
- 底部导航的每一项均分可用宽度，320px 也不折行；顶部在较窄手机下控制控件宽度与行距。保留 44px 级触控目标。
- `client.css` 最后层覆盖参考 CSS；不改参考原文件，不动后端 API 与数据模型。

## 验证与发布

Playwright 在隔离本地后端上跑真实业务页面，不拦截业务响应。先记录会失败的布局断言，再调整 CSS/模板；检查 320/390/430，桌面抽验。若交付至当前生产机试用实例，新版本仅更新 Web 静态资源，沿用现有受限 env、短信和 Prototype 配置，发布后公网抽验。
