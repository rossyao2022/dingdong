# 设计

## 运营登录验证码

新增 `/ops/captcha/` PNG 图形验证码入口，随机四位数字用标准库位图绘制。答案、生成时间只保存在 Django session；每次校验立即删除，最多有效 2 分钟。登录表单先检查验证码，再做账号密码验证。失败后浏览器重载新图片，不向 HTML/JSON 输出答案。

## 登录失败限流

按规范化用户名的 SHA-256 摘要做缓存键。生产环境的 Django 默认缓存连接独立 Redis DB，保证 Gunicorn 两 worker 共享计数。验证码通过后密码失败才计入；10 次/15 分钟临时限制，成功后清零。测试环境继续用进程内缓存。

## 公网路由

生产机 IP HTTPS 下的叮咚路由不再配置 `auth_basic`。Nginx 将技术管理页 `/admin/` 和 `/dingdong/admin/` 关闭公网入口；运营使用 `/ops/`。保留其他业务虚拟主机和 IP 根路径不变。Django 对后台页面继续使用 session/CSRF，对家长接口继续使用 JWT。切换顺序：先部署新应用与验证码、验证本机入口，再去掉外层 Basic，立刻公网浏览器验收。

## 发布与回滚

版本升至 v0.3.11，打新发布包。在生产机从 v0.3.10 现有镜像做代码覆盖构建，复用已安装依赖，不新增 Python 包；数据卷保持原样。变更前备份数据库和 Nginx 片段。失败时恢复旧片段、用原镜像与发布目录回退；不删除数据卷。
