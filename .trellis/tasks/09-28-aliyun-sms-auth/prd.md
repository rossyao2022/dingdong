# 阿里云短信验证码接入与实发验证

## Goal

把家长端现有的短信挑战、登录与 JWT 流程扩展为真实阿里云短信验证码，在独立新凭据下向用户指定手机号完成一次实发验证。固定码仅保留在显式演示/测试模式。

## Requirements

- 对照 Seewow 已有实现，但叮咚必须使用当前阿里云账号自己的 AccessKey，不复用 Seewow 的凭据。
- 核对短信服务与短信认证各自的额度、签名和模板。用户已选择号码认证的短信认证，并告知已购买 1000 条短信认证额度；以控制台实际状态为准。
- 保留叮咚当前的 CSRF、按手机与 IP 限频、一次性挑战、5 分钟有效期、错误次数上限、JWT 与家庭隔离；真实码不得进入响应、日志或 Git。
- 对阿里云发送失败保持关闭状态：不回“已发送”，不产生可用挑战，不回退到固定码。
- 在本地跑有意义的单元与集成测试，使用授权手机号实发并在收到码后完成登录验证；首条验证码过期后，用户已单独批准补发一条。记录脱敏证据和额度状态。
- 若需要修改外部云账号、生产机器或推送 Git，在满足仓库 NEED-GATE 后执行；不擅自复用或读取 Seewow 的密钥。

## Acceptance Criteria

- [ ] 实短信模式能用新 AccessKey、安全配置、短信认证的系统签名/模板向中国大陆手机号发送随机验证码，前端既有登录流程可用。
- [x] 固定码模式的既有自动化测试仍通过；实短信模式的发送成功、失败、限频、验证码错误、过期及一次性消费都有测试证据。
- [x] 用指定手机号实收一条短信并完成验证码登录；首次验证码过期后经用户单独批准补发，第二次完成真实登录。
- [x] 密钥、完整手机号和验证码不写入 Git、日志或公开文档；真实模式绝不接受固定码 `00000`。
- [ ] 部署和实测范围与用户授权一致，更新项目记忆、配置说明和运营指南中固定码相关内容。
