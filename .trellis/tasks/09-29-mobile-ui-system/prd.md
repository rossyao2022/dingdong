# 家长端移动界面整理与端到端验收

## 目标

用真实 Chrome 的手机视口逐页发现并修复家长端组件紧贴、按钮错位与窄屏文字折行；让后续页面继续沿用一套可预览的视觉构件。

## 要求

- 320×700、390×844、430×932 三档手机视口覆盖登录、建档、探索、今日陪伴、成长旅程、测评与报告、账户与关联，并抽查弹窗；桌面回归避免移动修复伤及既有视觉。
- 页面没有横向溢出；相邻卡片有稳定间距；按钮与相邻说明之间留足空间；底部导航在窄屏仍可完整辨认和点击；表单字段与提交按钮顺序、对齐一致。
- 建立与现有原生 JavaScript、三层 CSS 一致的 Storybook，至少展示按钮、操作组、卡片、页头、空态和窄屏示例。Storybook 与生产页面复用同一构件，不复制一套仅供展示的假样式。
- 现有登录、儿童档案、机器人绑定、测评/报告和其他业务请求行为不变；不引入 CDN 或运行时框架，不把技术语言加回家长界面。
- 每个修正点有可运行的浏览器布局断言，并以真实页面截图和测试结果验收。生产试用实例若发布新版，须保留现有短信与 DingDong Prototype 配置。

## 验收

- [ ] 指定手机视口与主要路由的横向溢出为 0，按钮可见且无重叠/遮挡。
- [ ] 320px 登录验证码区、成长观察日期区为清晰纵向布局；报告卡片相邻边距足够；底部导航标签不折行。
- [ ] Storybook 启动、静态构建成功，故事确实调用生产复用构件。
- [ ] 原有前端语法、单测和相关真实 Chrome 业务回归通过；如发布，公网移动视口抽验通过。
