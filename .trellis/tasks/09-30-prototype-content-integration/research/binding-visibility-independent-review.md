# 绑定状态展示独立复核（2026-10-01）

复核范围：相对 `cdb1599` 的 v0.3.26 全部改动；当前父任务 PRD、设计、实施记录及前端绑定/展会、状态渲染、API、验收规范。未操作生产、推送、短信或供应商。合成绑定场景不代表供应商真实握手。

## 已核对

- `robotVisibility` 仅使用当前儿童的 active 账号，bound/pending/unbound/unknown 明确分开；其他儿童及归档不误认为当前绑定。
- 我的 DingDong 与测评报告：bound 隐藏展会，保留个人报告/聊天/管理；未绑保留 CA 和可选展会，不显示管理/换机/解绑。报告读取成功或授权状态不代替绑定状态。
- 直接展会地址先读取当前绑定；已绑跳个人报告，账号读取失败只给重试，不加载共享报告。
- 取消连接和解绑按当前儿童、账号及 UI 状态核验；完成后真实重读账号。切儿童及报告晚响应沿用 epoch 保护。
- 修改不替换 CA 原功能、认证、家庭隔离、数据持久化或供应商契约。版本入口/模块依赖图统一为 0.3.26。
- 独立实跑 `npm --prefix frontend run test:unit`：121 passed，0 failed。版本图检查包含在本轮单测。
- 实施方真实 Chrome 初轮受隔离 fixed_code 测试库旧 SMS 挑战频控影响；不能当功能绿灯。后续日志已显示 390/1280 状态转换和真实离线传输故障共 3 项通过，故障不拦截/伪造业务响应。最终证据仍应包含页面脚本错误断言。

## 本轮发现与整改状态

1. **待修：取消未完成连接的并发状态保护。** `confirm-cancel-connection` 原实现只验旧 hints，随后调用无前置状态的通用 retire。若供应商晚成功或另一标签页重试使账号变 bound，取消会归档新 bound 账号，违背“取消未完成连接”。建议可选 `expected_bind_state=unbound` 入参，在事务中锁住实际账号并核验；不匹配 409 且不改账号/关联/审计。普通解绑旧空入参兼容。
2. **待修：旧 NFC robot_ref 不能带到下一台。** 原成功取消/解绑仅清 token 和 pending 标记，`hints.nfcRobotRef` 仍会被下次手动 token 提交携带。应清除旧设备元数据并通过真实 API 检查取消后新绑定的 robot_ref。
3. **防御分支：unknown 一致性。** 账号数组含未认识的 bind_state 时，账户页不应当 pending，报告页应给重试；当前数据库仅允许合法二值，属于契约漂移防护。账户页 guard 已见补齐，报告页仍应使用 visibility.state 判断。
4. **测试证据：pageerror。** 新状态浏览器测试应收集并断言页面脚本异常为空，不能只依赖 Playwright 默认行为。

以上已发给主实施者协调修复，本复核者没有并行修改运行代码。整改及最终复核结论在后续追加，当前不将待修项写成完成。

## 整改代码复核与追加弹窗范围

待修项已由实施者补齐代码：retire 可选状态前提在 child→account 行锁后核验；冲突发生在归档、关联结束及审计前，旧空请求仍兼容。取消/解绑和主动放弃 NFC 清除旧 robot_ref；账户和报告 unknown 状态给白话重试；Chrome 加 pageerror 断言。实施方后端全量本轮日志为 **498 passed**，含新取消状态保护与输入校验。

追加带 robot_ref 的真实 NFC 场景后，Chrome 曾发现有 token 时按钮叫“重新连接”、无 token 时叫“继续连接”的断言失败。这一轮不能使用较早的 3 项绿灯替代；已要求统一 pending 操作名称后再跑。

用户追加的组件确认同步纳入复核：共享 ui-components 的确认框转义文案、取消默认焦点、独立事件不进入全局 busy 动作；取消、Esc、关闭、pagehide 和 leaveContext 只结算一次且删除监听和元素。兴趣组合先构建候选，不在等待时清空旧答案或地图；确认 await 后先检查儿童/页面 token 与原 session 身份，再清缓存。IslandExplorer 的外层 ticket 同时防晚回覆盖。运行应用源码扫描已无浏览器原生 alert/confirm/prompt 调用；运营的 Ops.confirm/alert 是既有组件，未替换。

目前以上代码复核没有新增运行缺陷；最终还待新的绑定 Chrome、组件 Chrome 和全量前端检查证据齐备后核销。
