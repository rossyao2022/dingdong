# 生产机 DingDong Prototype 真源联调

## Goal

在 `1.15.23.152` 的叮咚试用实例上，用对方已交付的 Prototype 地址和测试 `X-API-Key` 验证真实网络、客户端、账户绑定与四个展示接口。依据实测列出正式生产接入的剩余条件和责任方。

## Requirements

- 使用生产机正在运行的应用代码及真实出站网络，不以本地 fixture 或历史记录代替供应商响应。
- 测试凭据与原始 NFC token 不进入 Git、命令输出或报告；保持当前家长和运营服务可用。
- 区分 Prototype 固定账号、正式 `ca_` ULID 账号、四子接口与聚合 insights、我方 webhook 自测与对方真实推送。
- 对不可达或契约不匹配的步骤如实记录，不将 Prototype 模拟数据称为正式生产数据。

## Acceptance Criteria

- [x] 生产机向 DingDong Prototype 完成健康、认证及只读端点调用，并记录业务码与响应形状。
- [x] 生产机运行的 CA 代码走一次真源展示路径；固定账号与我方正式账号分别验证绑定语义。
- [x] 判断能否安全把试用实例的数据源切到 DingDong；因正式账号拒绝、子接口缺数与 HTTP 限制，保留可用版本并写明证据。
- [x] 更新三方剩余事项、生产机配置/部署状态及联调证据，不泄露密钥。
