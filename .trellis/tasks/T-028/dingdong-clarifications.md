## 0. 背景对齐（一句话现状）

我方 8 个出站接口 `/api/v1/ca/*` **当前一个都没接通**：客户端骨架已就绪，但 `DINGDONG_BASE_URL` / `DINGDONG_API_KEY` 未配置时**显式报「尚未配置」并停止**，不伪造成功、不返回假数据。`ca_account_id` 一侧（发号 / 绑定 / 同机复用 / 异机换机信号 / 归档）已实现并有测试覆盖，**未部署、未发版**。四个展示面（人设 / 15–30 天成长报告 / 健康度四态 / 复测 CTA）设计已定稿，实现尚未开始。

**我方对外承诺的底线**（供贵方评估风险）：在贵方答复到达前，我方不会把任何未接通的能力对外描述为已接通；家长端不会出现凭猜测编造的人设、成长或健康度数值。

## 1. 阻塞级（3 项）

> 判据：没有答复，我方下一步的代码就写不下去，或写下去有返工风险。

### B1｜base URL：`mock` 与 `production` 的地址，以及「必须 HTTPS」约束的适用范围（D12）

**为什么需要**
base URL 是客户端第一个参数。文档表 12 要求「所有接口必须使用 HTTPS」，但没有给地址；表 12 也没说这条要求是否约束**我方入口**。

**当前降级**
`DINGDONG_BASE_URL` 为空时 `is_configured()` 为假，8 个出站接口一律不发出站请求，抛 `NOT_CONFIGURED`（文案「尚未配置 DingDong base URL 或 X-API-Key」，`action=stop`）。家长端不显示任何来自贵方的数值，只显示「待接通」状态。

**接入动作**
把两个地址写进按环境区分的运行时配置（不硬编码）；客户端侧强制 HTTPS 与超时；补齐 8 个接口的集成测试（用贵方 mock 端点还是表 6 账号，取决于 D11）。

### B2｜`X-API-Key` 的签发、轮换、两套环境与失效表现（D10）

**为什么需要**
密钥拿不到，客户端连不通。轮换周期决定我方要不要做「双 key 平滑切换」；失效表现决定我方是「停调并告警」还是「重试」。

**当前降级**
同 B1：`DINGDONG_API_KEY` 为空即视为未配置，零出站。业务码映射已按文档预留 `40101` → 停调 + 告警的分支，但没有真实 key 就无法验证它真的按预期触发。

**接入动作**
按环境分别注入（密钥只进运行时配置，不入版本库）；实现轮换期双 key 并存与灰度切换；补一条「key 失效 → 停调 + 告警 + 家长端显示同步暂停」的端到端用例。

### B3｜换机发新号后，旧号在贵方的 `user_persona_binding` 如何处置（D20）

**为什么需要**
我方已定案：**换一台机器人 = 换一个新 `ca_account_id`**，旧号置 `retired` 归档、永不重用（理由：历史报告要可查，号码回收会与贵方侧旧绑定撞号）。贵方这一半没定，我方的换机状态机就闭不了环：如果必须显式调用解绑接口，换机流程要多一步、失败时要能回滚；如果旧绑定会悬挂，家长换机后可能在贵方侧留下一个永远 `active` 的孤儿绑定。

**当前降级**
换机只走「确认弹窗 → 旧号置 `retired` → 发新号 → 调 `bind`」四步，**不实现主动解绑分支**；家长端保留旧号只读入口（按孩子 + 已 `retired` 的号查历史报告），并在换机确认弹窗里如实告知「换新设备后成长记录从新设备重新开始，旧设备记录仍可在历史中查看」。我方不会假装旧绑定已被释放。

**接入动作**
按答复补状态机分支：需要显式解绑 → 在换机流程里插入解绑调用并定义失败回滚；旧号 `growth_period` 仍可查 → 旧号只读入口改为读真源（现在读的是我方库存报告）；不可查 → 旧号入口明示「该设备时期的数据贵方侧已不再提供」。

### C2 儿童 / 设备映射与权属核验

**C2.1｜D18 — 机器人是否有稳定唯一标识；`nfc_token` 是否一机一码、终身不变、换绑后是否复用；同一 token 绑到另一个家庭返回 `40901` 还是允许覆盖**
- **为什么需要**：我方已定「一台机器人一个号、一台机器人服务一个孩子」，绑定关系要以机器人为主键落库。token 若会复用，会出现「同一 token 指向不同账户」的历史歧义，权属无法回溯。
- **当前降级**：我方只存 `nfc_token` 的 HMAC 摘要（不落明文），靠「活跃行对 token 摘要唯一」的约束挡住重复绑定；但**无法判断**贵方侧同一 token 是否已绑到别家——冲突只能在我方侧收到 `40901` 时才暴露。凭据读完即从地址栏摘掉，只留内存。
- **接入动作**：把机器人标识落进绑定表并做权属核验（token → 机器人 → 家庭三段可对账）；按答复实现换绑冲突分支（拒绝并提示「该机器人已绑定其他家庭」或允许覆盖）。

**C2.2｜D11 — Mock 形态，以及表 6 的 6 个 `ca_mock_*` 账号由谁初始化**
- **为什么需要**：决定我方联调怎么搭；账号没人初始化，联调就起不来。
- **当前降级**：不使用任何真实账号；联调前先按「贵方提供 mock 端点」的假设写测试，跑不通就停在这里如实报告，不改成假数据糊过去。
- **接入动作**：按答复接 mock 端点或用表 6 账号；把我方 6 个场景（对应表 6 的 6 个 mock 账号）接到集成测试里。

**C2.3｜D19 — `ca_account_id` 是否有格式 / 长度约束**
- **为什么需要**：我方已按 `ca_` + 26 位 ULID 发号并落库，号码一经发布即冻结；若贵方不接受，越晚改迁移成本越高。
- **当前降级**：按已定案格式发号；贵方只需按**不透明字符串**存储与回传，不需要解析其内部结构。
- **接入动作**：若格式不可接受，尽早迁移（我方承担）；若可接受，回一句确认即可关闭本条。

### C3 窗口游标修订与指标单位

- **接入动作**：按答复固定窗口口径并写进契约；若 `ca_mock_new_001`（`companion_delta=0` + `watch`）不是「数据不足」的表示，我方要改空态判定。

- **为什么需要**：`"null"` 字符串会被我方当有效值处理，产生脏时间轴；序列号直接入库会得到 1900 年的日期。

- **接入动作**：拿到文本示例后去掉换算兼容层；按贵方统一的空值写法收敛解析器。

**C3.3｜N1（新增）— 窗口重算与游标修订口径，以及指标的计数单位**

- **接入动作**：确认后去掉兼容分支、定稿字段名；若窗口会重算，加「同一周期多版本并存、以 `algorithm_version` + 返回值为准」的处理；拿到单位后在家长端补正确量词。

### C4 同步频率与阶段规则

**C4.1｜N2（新增）— 同步频率以哪份材料为准**
- **为什么需要**：表 2 逐表给了「更新频率」（首次 / 复测、人设发布、初测 / 复测 / 切换、建议每日、15/30 天、每日 / 报告时、触发 / 用户操作），项目管理材料的接口清单写的是「DingDong Data Feed：增量 / 持续」「Feature API：日更 / 按需」。两套说法决定家长端显示「数据更新到什么时候」，也决定「同步暂停 / 陈旧」的判定阈值。

- **接入动作**：确认后把频率与陈旧阈值写进配置；补「同步暂停 → 家长端显示同步暂停」的用例。

**C4.2｜D16 — `switch_candidate` / `keep_current` 由 `health.status` 还是 `complete` 响应的 `switch_recommended` 表达**

- **接入动作**：按答复收敛字段归属；若 `switch_candidate` 确实属于 `status`，四态要加第五态。

**C4.3｜N3（新增）— H01–H07 的阈值校准，以及 `growth_stage` / `trigger_type` 的判定规则**
- **为什么需要**：表 7.2 的 5 个阈值（`normal_delta_15d=20`、`watch_min_delta_15d=5`、`reassess_delta_21d=5`、`switch_match_delta=15`、`auto_switch=false`）注明「上线后根据真实用户分布校准」——请给校准后的取值与生效方式（贵方侧改还是通知我方改）。另外 `growth_stage`（`initial` / `exploring` / `developing` / `deep` / `co_creation`）与 `reassessment_event.trigger_type`（`low_engagement` / `periodic` / `manual`）**没有给判定规则**，我方只能展示贵方返回值，无法在界面解释「为什么现在是这个阶段」。
- **当前降级**：`auto_switch` 我方恒按 `false` 处理——**任何路径都不自动切换人设**，切换一律由家长确认；阶段与触发原因只原样展示贵方返回值，不自行推断。
- **接入动作**：拿到阈值后写进配置（我方不硬编码业务阈值）；拿到阶段判定规则后补家长端解释文案；若阈值只在贵方侧改，约定变更通知方式。

**C4.4｜D17 — `talent_weight_version`（`pw_v1`）/ `algorithm_version`（`growth_v1`）的升级策略**
- **为什么需要**：升级后旧的 `growth_period` 是否仍可查、会不会在同一周期看到两个版本的数据。
- **当前降级**：按「多版本并存、以返回值为准」实现，不做版本过滤，也不在我方侧重算。
- **接入动作**：确认后决定报告上是否标注版本；若旧版本会被清理，我方要提前缓存或改展示。

### C5 甲方算法输入输出 / 超时幂等 / 一次性处理不留存

**C5.1｜D6 — 首次测评的画像通过什么通道交给贵方做「人设匹配」**
- **为什么需要**：**这是当前最大缺口**。表 0 写「DingDong：读取画像进行人设匹配」、表 3 标 `ca_user_profile`「CA 写」，但 8 个接口里没有提交画像的接口，`account/bind` 的样例请求只有 `ca_account_id + nfc_token`。没有这条通道，绑定后人设、成长、健康度三条链全部起不来。
- **当前降级**：不猜通道、不伪造「已匹配」。绑定成功后家长端如实显示「待接通」；画像留在我方库（`ProfileSnapshot` 不可变），随时可提交。
- **接入动作**：拿到通道（接口或替代读取方式）后实现提交 / 读取。这是唯一会同时解开人设、成长、健康度三条链的一项。

**C5.2｜D9 — `complete` 之后 `new_persona_id` 何时生效、新角色推荐取哪个接口、家长确认切换要不要再调接口**
- **为什么需要**：「不自动切换人设」是硬约束，家长确认动作的落点必须清楚——是调接口，还是贵方按 `persona_switched` 自行推进。
- **当前降级**：家长确认时只落本地标记，**不自动切换**；新角色推荐暂取 `complete` 响应，真源切换前必须确认。
- **接入动作**：按答复实现确认动作的落点；若需再调接口，补一次写操作与幂等。

**C5.3｜D5 — `request_id` 的字段名、位置（请求头还是 body）、幂等窗口、重复请求的返回**
- **为什么需要**：幂等键定不下来，绑定与复测回写这两个写操作无法安全重试——网络抖动后重试可能造成重复绑定或重复切换。
- **当前降级**：客户端已按「请求头带 `request_id`」实现并记录本地重放结果，但这只是我方假设、未与贵方对齐。写操作在我方侧**先落本地状态、再出站**，出站失败留重试。
- **接入动作**：按答复调整字段位置与窗口；补「同 `request_id` 重放返回首次结果」的用例。

**C5.4｜D4 — 唯一错误码表、`message` 是否必返、`40901` 的具体触发条件**
- **为什么需要**：我方要实现 7 个业务码的分支（`42901` 延时重试、`40101` 停调告警、`40401` 当「暂无数据」、`40901` 冲突、`40001` 致命）。码表不全就写不全；`message` 是否必返决定我方能否把贵方文案直接透给家长，还是必须自己兜底。
- **当前降级**：已按 docx 第 9 节的码表实现映射；**`message` 缺失时用我方兜底文案**，不把空串或 `undefined` 显示给家长；未知码落「未知错误 + 保留重试」，不吞掉。
- **接入动作**：拿到唯一码表后补齐分支；若 `message` 必返，改为优先透传贵方文案。

**C5.5｜N4（新增）— 正式量表 / 适龄 / 题量 / 评分解释**
- **为什么需要**：我方画像的输入是测评量表。量表的适龄范围、题量与评分解释没定，画像的语义就定不下来；而画像正是贵方做人设匹配的输入（C5.1）。这一项不解决，人设匹配的输入质量无法评估。
- **当前降级**：按现有量表跑通流程，不对外宣称它是正式量表；评分解释不写进家长端的结论性文案。
- **接入动作**：量表定稿后重跑基线、给出评分解释文案，并按 D6 的通道提交画像。

**C5.6｜N5（新增）— 甲方算法对原图的一次性处理与不留存约定**
- **为什么需要**：我方对指纹图片的约束是「一次性处理、不留存」——图片不进数据库、对象存储、任务队列、日志、错误追踪、调试抓包文件或备份；算法调用采用有界请求处理，不把图片放进持久任务等待重试。贵方算法**是否需要原图、能否一次性处理且不保存、是否在日志或训练中使用**，必须逐条核实。
- **当前降级**：我方**不宣称**外部算法已满足这些要求；核实前不把图片交给任何外部算法做持久化调用。
- **接入动作**：拿到逐条答复后写进对接契约；若贵方需要原图，我方要重新评估「图片不留存」的实现边界，而不是默默放宽。

**C6.1｜N6（新增）— `new_assessment_id` 的取值语义与 `complete` 的幂等窗口**（前置项）

**C6.3｜N8（新增）— `persona_type` 与 `learning_style_tags` 的 code 表**

**C6.4｜N9（新增）— `growth_period` 八维全部可空时，是否允许只返回部分维度**
