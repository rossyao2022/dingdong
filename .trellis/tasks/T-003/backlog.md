## 一、家长端体验问题

### P-01 绑定机器人成功后没有任何反馈，还被带回首页
- **卡在哪**：家长在「账户与关联」点「绑定机器人」→「确认绑定」，对话框一关，页面跳回首页，家长不知道成没成、也看不到刚生成的账户号；必须自己切回「账户与关联」才发现多了「当前机器人 ca_01M2PZQM5RNBPNVQXJ5CXEWDMN」。
- **现状**：`POST /api/v1/children/{child_id}/ca-accounts` 返回 201，但界面无成功提示、`location.hash` 变回空（回首页）。同一会话里 `#toast` 区域为空。
- **建议改法**：绑定成功后**留在账户页**并高亮新号，配一行「账户号已生成，等机器人接通后开始同步」（这句话后端已经返回了状态，界面只是没显示）。
- **完善/扩散**：完善。
- **工作量档位**：小。

### P-02 手动点「绑定机器人」的家长不知道该填什么凭据
- **卡在哪**：对话框正文只说「机器人上的标签会带着凭据打开这个页面」，输入框 placeholder 是「从机器人标签上取得」；从按钮进来的人手里根本没有凭据，不知道去哪拿、该填什么格式。
- **现状**：凭据留空点「确认绑定」→ 对话框不关，靠 `<input required>` 的浏览器原生气泡挡下，页面自己的 `.form-error` 是**空且隐藏**的（`vis=false, h=0`）。
- **建议改法**：补一句操作指引（「用手机碰一下机器人上的标签，会自动带凭据回到这里」），并在手填时给出格式/长度提示，把校验错误落到 `.form-error` 里而不是只靠原生气泡。
- **完善/扩散**：完善。
- **工作量档位**：小。

### P-03 授权同意框的信息量不足以支撑信任

- **现状**：对话框全文即上述一句 + 「我已阅读并同意本次测评用途」+「同意并开始」。

- **完善/扩散**：完善。
- **工作量档位**：小（文案 + 模板）。

### P-04 内部标识 `readable-v2` 直接暴露给家长

### P-06 「成长观察」填了非法时间区间，点了没反应

- **建议改法**：就地提示「结束时间要晚于开始时间」，并把两个输入框标红。
- **完善/扩散**：完善。
- **工作量档位**：小。

## 二、运营后台体验问题

### O-01 真缺陷：CA 账户页把 Django 模板注释渲染成了页面正文
- **卡在哪**：运营打开「CA 账户」，页面最上方是一行 **`{# 注意：Tabler 的 .alert 是 flex 容器，散落的文本节点会各占一列。 内容必须包在一个块级容器里，与其他页面保持一致。 #}`** —— 像开发留下的垃圾。
- **现状**（已定位根因）：`backend/dingdong_ca/ops/templates/ops/ca_accounts.html:10-11` 写的是**跨行** `{# … #}`。Django 的模板标签正则 `({%.*?%}|{{.*?}}|{#.*?#})` **不带 `re.DOTALL`**（本机实测 `django.template.base.tag_re.flags & re.DOTALL == False`），所以跨行注释不生效，整段当普通文本输出。全仓扫描 `.trellis` 外的 ops 模板：**只有这一处**（1 处 / 1 文件）。
- **建议改法**：换成 `{% comment %}…{% endcomment %}` 或压成单行 `{# … #}`。
- **完善/扩散**：完善（纯缺陷修复）。
- **工作量档位**：小。

### O-02 家长姓名为空时，五处界面回落到内部登录账号 `parent-<uuid>`

## 四、稳定性（单列）

### S-01 错误态
- 已确认**缺失**：P-05（422 原始报错透传）、P-06（非法区间静默无响应）、P-07（慢网无进行中提示）。
- 已确认**良好**（对照，不是问题）：断网时家长端给出「连接中断，操作结果可能尚未返回。请查询最新状态或重试。」（`offline` 实测，可见）；验证码限频时给出「请稍后再次获取验证码」（`POST /api/v1/auth/sms` → 429，`.form-error` 可见）；错误验证码给出「验证码错误」。
- 本轮零脚本错误：家长端六个视图挂载 error/unhandledrejection 监听后全部为空数组。

### S-02 空数据态
- 家长端空态齐且有解释：「0 完成活动 / 第一份记录，等你来留下」「还没有已生成的报告 + 出现条件」「还没有提交过服务事项」「呱呱 还没有机器人账户号」。
- 运营端空态齐：生成任务 `?only_problem=1` → 「共 0 条，每页 20 条。」+「没有符合条件的任务」「没有匹配的生成任务。」；筛选控件会正确回显（`select[name=only_problem].value == "1"`）。
- **但空态只在演示数据下验证过**：本轮运营后台「家庭总数 21 / 在册儿童 20 / 近 7 天新增儿童 20」，即演示库几乎全是近期测试数据，生产量级下的分页与空态未验证。

### S-03 网络慢 / 断
- 断网：家长端有明确中文提示（见 S-01）。
- 慢网（4s 延迟）：请求进行中界面无任何指示（P-07）；未观察到超时后自动放弃或重复提交。
- 未测：弱网下的长任务（报告生成/同步）家长端轮询行为，本轮未注入对应任务。

### S-04 celery 失败可见性
- 运营端**有**：工作首页「报告生成异常」「等待依赖的任务」两个计数（含口径说明，本轮均为 0）+ 生成任务页「只看问题」筛选、失败原因列、`重试` 入口。
- 家长端**有**（测评路径）：`frontend/app.js:360` 的 `report_status === "failed"` 分支给出「报告生成失败，请提交服务事项，由工作人员处理。」，并附「提交服务事项」入口。
- **未验证**：阶段画像/数据同步失败在家长端是否可见（本轮本地库失败任务为 0 条，要验证需 `inject_fixture` 注入真实失败任务；本轮未注入，不据文档记录声称通过）。

### S-05 e2e 因本地数据漂移失败的 4 项（**文档记录，本轮未复跑**）
来源：`PROJECT_MEMORY.md`（v0.3.4/v0.3.5 段）与 `deploy/evidence/**`。按仓库纪律不把历史数字当现状，故此处标注为待复跑项：
1. `frontend/tests/flows.spec.js` 本地 **3 项失败**：该 spec 走 `npm run dev`（`server.cjs` 代理到 127.0.0.1:8017），而用例内部的 `inject_fixture` 走 `uv run manage.py`，两者连的**不是同一个库** → 注入报 "Child does not exist"。
2. `frontend/deployment-tests/ops-public.spec.js` 本地 **1 项失败**（「报告」用例）：本地 `compose up` 会重新 seed，`ReportVersion` / `BackgroundJob` 为 0，报告列表无行可看；同一用例在公网（有真实失败任务）通过。
3. 上述 3+1 = **4 项**即"因本地数据漂移失败"的用例。另有一项环境绑定用例不计入这 4 项：`frontend/deployment-tests/http-profile.spec.js` 本地跑不了，因为它断言 `window.isSecureContext === false`，而 Chromium 把 `127.0.0.1` 视为安全上下文（只有真实 HTTP 公网入口成立）。
