## 完成的业务行为

| 流程 | 实现与验证 |
|---|---|
| 身份核验 | 核验凭据绑定家庭、有效期、一次消费、幂等；一个儿童/外部主体只有一个有效关联 |
| 主动同步 | Worker 主动读数据库测试数据源，定时扫描到期关联；不提供 DingDong 调用 CA 的接收端 |
| 重复与修订 | 同版本同内容不重复结果；合法修订引用上一版本；冲突保留旧值并标 stale |
| 游标 | 来源写入、阶段任务创建和进度更新处于同事务；失败不推进 |
| 授权/关联 | 读取及提交前复核；撤回、解绑、暂停阻止新结果，恢复须授权仍有效 |
| 阶段画像 | 固定观察来源和规则版本；仅合成 test-count-v1 计算，不混入网页活动次数 |
| 新规则 | 为最新观察生成新任务与画像，旧报告保持原内容；跨规则不可直接比较趋势 |
| 成长总览 | 区分无关联、无授权、未同步、无数据、故障和旧值；趋势仅比较相邻等长且兼容的窗口 |
| 报告与恢复 | 等待规则/模板、有限重试、人工恢复、租约接管、迟到 Worker 防重复 |
| 后台权限 | operations/content/technical/account_admin；Session+CSRF，家长 JWT 拒绝，禁止自提权 |
| 后台操作 | 草稿编辑、发布、重试、暂停/恢复、事项处理、员工角色/状态按钮；复用同一 API |
| 删除 | 在儿童锁下清理关联、进度、观察、画像、报告、任务、测评、授权、活动及该儿童 fixture；审计目标去标识；回执 child_id=null |

后台菜单保留固定业务范围，没有菜单配置器、角色编辑平台或接口权限树。发布内容不能在后台直接编辑，需创建新版本。账号管理员不能通过业务 API 修改自己、超级管理员或其他账号管理员。

## 数据与字段边界

所有新增输出仍为 synthetic。固定窗口的 test_observation/count、test-count-v1 和测试序号游标仅用于验证业务流程，不能解释为真实设备协议或儿童专业评分。

真实 DingDong 联调仍需确认：儿童主体如何唯一识别、核验凭据如何取得、获取 API 和认证、窗口与游标、修订/版本规则、观察指标及缺失语义、调用频率和超时语义。没有新增画像/配置推送，也没有保存指纹或原始供应商报文。

当前支持完整窗口的单条聚合输入。若供应商提供事件流、多批次聚合或不同窗口，需要在确认契约后扩展适配器及来源选择规则，不能直接套用测试字段。

题库更新时，`inject_fixture` 默认引用当前发布版；验证旧会话时可指定 `--questionnaire-version-id UUID`。19 场景的注入与实际动作见 `M3_SCENARIOS.md`。没有通用清库/reset 命令，冷启动隔离采用 pytest 的独立 PostgreSQL 测试库。
